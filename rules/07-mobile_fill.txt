STEP 7 -- mobile_fill ("Missing Mobile Numbers")
================================================================================
TYPE      manual_edit (pages 200 flagged rows at a time)
CODE      backend/app/pipeline/stages/mobile_fill.py :: mask_mobile_missing,
          validation_reasons_mobile

WHAT IT DOES
Flags accounts with no usable phone number for manual entry. No earlier
step blanks or sentinels bad numbers -- all three conditions below are
checked directly by this step's own validator.

CONSTRAINTS (a row is flagged if ANY of these is true)
  1. PHONE_NUMBER equals the sentinel value XXX_NOT_COLLECTED_XXX.
  2. PHONE_NUMBER is blank/empty.
  3. PHONE_NUMBER is all zeros (fullmatch regex ^0+$).
All three -> the same reason: "Phone number is missing or not a valid
number."

EDITABLE FIELDS
PHONE_NUMBER.

CONTEXT COLUMNS SHOWN (read-only)
ACCOUNT_NUMBER, ACCOUNT_FIRST_NAME, ACCOUNT_LAST_NAME.

ADVANCE RULE
Re-validates after every batch. Advances once zero rows remain flagged, or
immediately on force_advance=true (rows left with a missing/sentinel phone
number are not revisited later in the pipeline).
