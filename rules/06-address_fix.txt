STEP 6 - address_fix ("Address & Contact Auto-Fix")
Type: auto (runs automatically, no operator input)
Source: backend/app/pipeline/auto_stages.py :: stage_address_fix
         backend/app/pipeline/constants.py :: INVALID_ADDRESSES,
         BAGHDAD_ADDRESS_POOL, PROVINCE_ADDRESS_MAP
         backend/app/pipeline/utils.py :: balanced_assign

Requires columns PHONE_NUMBER, ADDRESS_CITY, ADDRESS_PROVINCE,
ACCOUNT_ADDRESS to exist -- the step raises an error and the job halts if
any is missing.

RULE 1 - PHONE NUMBER
If PHONE_NUMBER is blank, OR matches all zeros (regex ^0+$), replace it with
the sentinel value XXX_NOT_COLLECTED_XXX.

RULE 2 - WHAT COUNTS AS AN "INVALID ADDRESS"
ACCOUNT_ADDRESS is invalid if it exactly equals one of a fixed blacklist of
known-junk values (~60 exact strings) -- placeholders like "-", "0",
"00000", obvious phone numbers, dates, single letters/digits, etc. See
INVALID_ADDRESSES in constants.py for the full literal list. Anything not
in that exact list is treated as a valid address and left untouched.

RULE 3 - REPAIR LOGIC (evaluated in this order, first match wins per row)
  a) ADDRESS_PROVINCE (case-insensitive) == "outside the country" AND
     address is invalid
     -> ADDRESS_CITY = "Baghdad", ADDRESS_PROVINCE = "Baghdad",
        ACCOUNT_ADDRESS assigned from the Baghdad address pool.
  b) ADDRESS_CITY == "00000" AND address is invalid
     -> same fix as (a): forced to Baghdad city/province + pool address.
  c) ADDRESS_CITY != "00000" AND address is invalid
     -> look up ADDRESS_PROVINCE in PROVINCE_ADDRESS_MAP (covers the 19 Iraqi
        governorates with 2-5 real street/neighborhood options each).
        If the province has a pool, ACCOUNT_ADDRESS is assigned from it.
        If the province is NOT in the map, the address is left invalid and
        UNCHANGED (counted as "unmapped" in the summary) -- city/province
        are also left unchanged in this branch.
  d) ADDRESS_CITY == "00000" AND address is NOT invalid
     -> ADDRESS_CITY = "Baghdad", ADDRESS_PROVINCE = "Baghdad" only;
        ACCOUNT_ADDRESS itself is left as-is.

RULE 4 - POOL ASSIGNMENT ALGORITHM (balanced_assign)
When multiple rows need an address from the same pool, addresses are
distributed as evenly as possible across the pool (round-robin, not fully
random) and then shuffled with a FIXED random seed (42), so results are
reproducible given the same input and row grouping.

No manual review; the step just reports counts of phones blanked, addresses
repaired, and addresses left unmapped due to an unrecognized province.
