STEP 9 -- final_id_check ("Final ID Validation")
================================================================================
TYPE      manual_edit (pages 200 flagged rows at a time; skipped while
          BYPASS_MANUAL_EDIT_STAGES is on)
CODE      backend/app/pipeline/stages/final_id_check.py :: final_id_check_invalid_mask
          backend/app/pipeline/toolbox.py :: id_missing_mask
          (shared with default_id)

WHAT IT DOES
Last ID check after Haider's reply has been merged. DOB is NOT re-checked
here.

NO FORMAT CHECK. Whatever ID Haider filled in is accepted as final, even if
it doesn't match the Passport / National Id format from step 5. An ID only
counts as missing when:
  1. ID_TYPE or ID_NUMBER is blank (or already XXX_NOT_COLLECTED_XXX).
  2. ID_TYPE is "doc".
  3. ID_NUMBER is made only of zeros.

IDs that were sent to Haider and that he left blank or didn't return are
already set to XXX_NOT_COLLECTED_XXX when his file is merged (see
05-id_dob_validate.txt, "NAMES AND IDS AT STAGE 3").

EDITABLE FIELDS
ID_TYPE, ID_NUMBER.

CONTEXT COLUMNS SHOWN (read-only)
ACCOUNT_NUMBER, ACCOUNT_FIRST_NAME, ACCOUNT_LAST_NAME.

ADVANCE RULE
Re-validates after every batch. Advances once zero rows remain flagged, or
immediately on force_advance=true. Any row still missing an ID when this
step ends is handed to step 10 (default_id), which sets ID_TYPE and
ID_NUMBER to XXX_NOT_COLLECTED_XXX (no ID is generated).
