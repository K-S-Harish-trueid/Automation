STEP 5 -- id_dob_validate ("Missing ID & DoB")
================================================================================
TYPE      manual_edit (pages 200 flagged rows at a time)
CODE      backend/app/pipeline/stages/id_dob_validate.py :: compute_dob_validity,
          mask_id_dob_invalid, validation_reasons_id_dob
          backend/app/pipeline/toolbox.py :: compute_id_validity, id_reason_checks,
          series_available, parse_dob_series (shared with final_id_check/default_id)

WHAT IT DOES
A row passes only if it clears ALL THREE checks below: ID type valid, AND
ID number valid for that type, AND DOB valid. Anything else is flagged.

DEFINITION -- "available"
Not blank after trimming, and not one of the placeholder values (checked
case-insensitively): "", "0", "00000", "null", "none", "na", "n/a",
"xxx_not_collected_xxx".

CHECK 1 -- ID_TYPE
  1. ID_TYPE must be available (see definition above); otherwise invalid.
  2. If ID_TYPE (case-insensitive) == "doc" -> ALWAYS INVALID.
     -> reason: "ID type 'doc' is not accepted. Use Passport, National Id,
        or Civil Id."
  3. Accepted values (case-insensitive), anything else is invalid:
       "passport"
       "national id" / "nid" / "nationalid"
       "civil id" / "civilid" / "civil_id"
     -> reason (for blank or unrecognized, non-"doc" values): "ID type
        must be Passport, National Id, or Civil Id."

CHECK 2 -- ID_NUMBER (only meaningful once ID_TYPE is one of the three
accepted types; never checked for "doc" or an unrecognized type)
  1. Passport -> ID_NUMBER must fullmatch [A-Za-z][A-Za-z0-9]{7,8} (one
     letter followed by 7-8 more letters/digits = 8-9 characters total,
     first character must be a letter).
     -> reason: "Passport number must contain 8-9 alphanumeric characters
        and start with a letter."
  2. National Id -> ID_NUMBER must fullmatch \d{12} (exactly 12 digits, no
     letters, no separators).
     -> reason: "National ID must contain exactly 12 digits."
  3. Civil Id -> ID_NUMBER just needs to be "available" (see definition
     above) -- no format/length check at all.
     -> reason if missing: "Civil ID number is required."
  4. If ID_TYPE itself is invalid/unrecognized, ID_NUMBER is reported as
     unverifiable.
     -> reason: "ID number cannot be validated until a valid ID type is
        selected."

CHECK 3 -- DATE OF BIRTH (ACCOUNT_HOLDER_DOB)
  1. Must be available (see definition above).
     -> reason if not: "DOB is missing."
  2. Must parse as a real date -- tries the exact format
     "%Y-%m-%d %H:%M:%S" first, then falls back to a flexible day-first
     parse.
     -> reason if neither succeeds: "DOB is not a recognized date."
  3. Parsed date must be strictly after 1 January 1905 (1905-01-01 itself or
     earlier is treated as a placeholder/default date).
     -> reason: "DOB must be after 1 January 1905."
  4. Age must be >= 18 years, computed as (DATE_OPENED - DOB) in days /
     365.25 (falls back to today's date if DATE_OPENED can't be parsed).
     -> reason: "Customer was under 18 when the account was opened."

EDITABLE FIELDS
ID_TYPE, ID_NUMBER, ACCOUNT_HOLDER_DOB.

CONTEXT COLUMNS SHOWN (read-only)
ACCOUNT_NUMBER, ACCOUNT_FIRST_NAME, ACCOUNT_LAST_NAME.

ADVANCE RULE
Re-validates after every batch. Advances once zero rows remain flagged, or
immediately on force_advance=true. Rows still ID-invalid when this step is
skipped are picked up again at step 9 (final_id_check); the DOB check
itself is NOT repeated later in the pipeline.
