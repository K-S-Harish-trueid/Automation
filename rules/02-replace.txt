STEP 2 - replace ("Data Consistency Update" / historical override)
Type: upload (skippable)
Source: backend/app/pipeline/upload_stages.py :: stage_replace_reference,
         validate_replace_reference_inputs
         backend/app/pipeline/constants.py :: REPLACE_MAPPING_COLS

INPUT VALIDATION (upload is rejected if any of these fail)
1. A reference file must be supplied.
2. Both the base dataset and the reference file must contain ACCOUNT_NUMBER.
3. Both the base dataset and the reference file must contain every column in
   REPLACE_MAPPING_COLS (see below). Missing columns on either side reject
   the upload with an explicit list of what's missing.

MATCHING RULES
1. Matching key: ACCOUNT_NUMBER, compared as a whitespace-trimmed string on
   both sides (not numeric comparison).
2. If ACCOUNT_NUMBER repeats within the reference file, rows are sorted by
   ACCOUNT_NUMBER and only the LAST occurrence for each duplicate is kept.
3. Accounts present in the base dataset but absent from the reference file
   are left completely unchanged (their current values stand).

FIELDS OVERWRITTEN FOR MATCHED ACCOUNTS (REPLACE_MAPPING_COLS)
ACCOUNT_LAST_NAME, ACCOUNT_FIRST_NAME, ACCOUNT_MIDDLE_NAME, DATE_OPENED,
ACCOUNT_HOLDER_DOB, ACCOUNT_TYPE, CARD_TYPE, ACCOUNT_ADDRESS, ADDRESS_CITY,
ADDRESS_PROVINCE, ADDRESS_COUNTRY, POSTAL_CODE, PHONE_NUMBER, EMAIL_ADDRESS,
ID_TYPE, ID_NUMBER, ID_COUNTRY, NATIONALITY, ISSUING_FI, CARD_PROGRAM,
CARD_STATUS, SECONDARY_CARD_TYPE.

FIELD EXPLICITLY NEVER TOUCHED
CARD_NUMBER is never overwritten by this step, even for matched accounts.

SKIP RULE
This step is marked skippable: an operator may advance past it via
POST /jobs/{id}/skip without uploading any file. Skipping performs no merge
at all -- every account keeps its current values, identical to an account
that simply had no match in a reference file.
